# Reproducibility scope

## Five validation gates

### 1. Identity preservation

Persistent feature IDs are checked across the design catalog, materialized
geometry, reference population, visibility population and expected projection
outputs.

### 2. Geometric consistency

For every materialized station the verifier recomputes `||R-L||_2` and compares
it with the prescribed feature width.

This is a station-level boundary-separation check. It does not test preservation
of design-level family morphology, curvature or centerline shape after
surface placement/materialization.

### 3. Lineage completeness

The verifier closes each feature lineage from design catalog to materialized
geometry, reference population, 12 feature-view bindings and expected observable
projected bindings.

A generated `results/lineage_closure_40.csv` provides the feature-level audit.

### 4. Reference consistency

The constructed metric reference is recomputed directly from station-level L/R
widths, aggregated by persistent feature ID, and compared with the prescribed
width and frozen expected reference table.

### 5. View coverage

All 480 binary masks are reread. Foreground pixels and observability states are
recomputed and compared with the frozen visibility manifest.

Expected population:

- 396 observable bindings;
- 84 not-observable bindings.

## Additional reproducibility checks

For the 396 observable bindings the package also recomputes:

- station-level camera projection;
- positive-depth and image-domain validity;
- projected L/R width in pixels;
- binding-level projected-width statistics;
- global projected-scale statistics;
- prescribed-width grouped projected-scale summaries.

Projected scale is additional characterization, not a validation gate.

## Frozen UAV inputs

The public UAV reproduction starts from:

- `data/parameterization/feature_design_40.csv`;
- `data/uav_validation/geometry/geometry_lcr_4530.csv`;
- `data/uav_validation/cameras/cameras_12.json`;
- `data/uav_validation/visibility/visibility_manifest_480.csv`;
- 480 binary visibility masks.

Therefore, this package does not claim to regenerate the UAV materialized
geometry or visibility masks from raw imagery/support-surface inputs.

## Intentionally excluded historical stages

- raw RGB ingestion;
- EXIF extraction;
- support-surface reconstruction;
- historical UAV surface placement/materialization;
- visibility-mask generation/rasterization and occlusion processing;
- historical TRAIN+VAL selection;
- absolute georeferencing;
- historical HPC/JPRS stages.

## Neutral reference example

The neutral example is independently generated by
`src/reproduce_neutral_example.py`. It is not a numerical replica of the UAV
validation case.
